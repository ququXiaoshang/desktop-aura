# 灵动桌面 Aura — 第二阶段功能提案

> 状态：**提案，未动代码** ｜ 调研时间 2026-10-19 ｜ 基线版本 0.2.0
> 目的：在阶段 A（复刻 + 分组 + 切模式）完成后，决定第二阶段做什么。

---

## 0. 先看结论

**定位建议：不要去和 DeskBox / Fences 拼"整理能力"，要拼"手感 + 零配置 + 记得住"。**

整理类功能（盒子、标签页、规则、一键归类）竞品已经做得又全又重，正面硬刚没有胜算；
但"**桌面图标会动、会呼吸、跟着鼠标有反应**"这件事，目前没有一家认真做——这是我们的天然护城河。

所以第二阶段建议按「**先能用 → 再顺手 → 最后好看**」的顺序：

1. **能用**：把「桌面真实文件 / 文件夹」「多屏」补上——现在灵动模式会把桌面文件和文件夹"吃掉"，这是发版级问题。
2. **顺手**：右键菜单、规则自动归类、搜索启动、撤销、图标排序——这些是日常使用的摩擦点。
3. **好看**：动效主题包、壁纸取色、磁吸/视差、悬停信息卡——做出记忆点。

推荐的第一刀：**v0.3.0「能用」** = 桌面真实文件 + 多屏 + 右键菜单 + 启动失败反馈。

**四条结论**

1. 竞品全是"整理器"，我们是"动效层"——**别做第二个 Fences**，把动效做到别人没有的高度。
2. 它们的基本盘（真实文件、右键、规则、搜索、撤销）我们必须补齐，否则用户装完第一天就退回原生桌面。
3. 分发层面我们最弱：它们有安装器、签名、多语言、自动更新；我们只有一个 zip + 0 下载。
4. 公开仓库已有 1 star、0 下载，说明**还没进入自然传播**，现阶段"能用 + 有记忆点"比"功能多"更重要。

## 3. 功能池（按优先级）

> 工作量为**粗估**（按我现在这套代码的熟悉度），单位"人日"，仅供排序参考。

### 3.1 P0 — 补漏（不做就不该发版）

| 编号 | 功能 | 解决什么 | 实现要点 | 粗估 |
|---|---|---|---|---|
| F1 | **桌面真实文件 / 文件夹纳入** | 灵动模式吞掉桌面文件，最致命 | `listDesktopItems` 放开扩展名过滤；文件夹用 `fs.statSync` 识别并取 Shell 文件夹图标；文档走现有 `ExtractAssociatedIcon` | 1 |
| F2 | **多屏 + 高 DPI** | 副屏不显示 | 按 `screen.getAllDisplays()` 每屏建一个覆盖层（同一渲染页）；`screen` 变化时重建；命中检测天然按窗口隔离 | 2 |
| F3 | **启动失败反馈** | 点了没反应 | `shell.openPath` 返回非空字符串即失败 → 图标抖动 + 托盘气泡/toast | 0.3 |
| F4 | **单击/双击启动可配置** | 误启动 | 加 `behavior.openOn: 'single'|'double'`，默认 `double`（与系统一致），config 只增字段 | 0.5 |

## 4. 三个可选冲刺方案

| 方案 | 版本 | 范围 | 粗估 | 得到什么 |
|---|---|---|---|---|
| **A「能用」**（推荐） | v0.3.0 | F1 + F2 + F3 + F4 + F12 + F13 | ≈ 4–5 天 | 可以放心给非程序员用：文件不丢、副屏能用、点错了有反馈、图标实时更新 |
| **B「顺手」** | v0.3.x | F5 + F6 + F7 + F8 + F9 + F11 | ≈ 6–7 天 | 日常摩擦降到和 Fences 同级；适合自己长期当主力桌面 |
| **C「好看」** | v0.4.0 | F14 + F15 + F16 + F17 + F18 | ≈ 4–5 天 | 做出别家没有的观感，截图/视频更适合传播 |
| D「能打」 | v0.5.0 | F10 + F21 + F7 | ≈ 6–7 天 | 真正进入"桌面整理"赛道，但正面竞争 |

**推荐节奏：A → C → B。** 理由：A 解决"敢不敢装"，C 解决"值不值得推荐"，B 解决"用久了烦不烦"；
B 里的右键/规则/搜索工作量最大且最不容易出彩，放在有用户之后再做也不迟。

## 5. 风险与明确不做

**风险**

- **多屏**：不同 DPI 的副屏会让 CSS 像素和系统图标间距对不上，需要按 `display.scaleFactor` 换算；建议先只支持"同 DPI 多屏"。
- **右键菜单**：覆盖层不可聚焦，原生菜单可能立即消失——先用自绘，别赌原生。
- **文件操作**（重命名/删除）：必须在容器内二次确认，误删不可逆（回收站可救，但仍需谨慎）。
- **搜索启动**：切换可聚焦会短暂抢焦点，需在失焦时立刻退回穿透，否则会挡住桌面右键。
- **取色**：浅色壁纸下白字看不清，取色后要同时算"文字底衬"亮度。

**明确不做**

- 不做实时折射毛玻璃（需要截屏或 DWM 私有接口，收益小、性能差）。
- 不做文件"移动/复制"式整理（保持"只引用"，这是相对竞品的信任优势）。
- 不引入前端框架（维持原生 HTML/CSS/JS）。
- 不默认依赖 Everything（可做可选集成）。
- 不碰任务计划（自启只走 `HKCU\...\Run`）。
